# Lessons from OpenAI, Anthropic and Google memory

Primary-source research checked September 12–13, 2026. Consumer-product behavior, developer interfaces and model-architecture research are separate evidence categories. Public sources do not disclose complete private implementations, and do not establish that an SDK can turn a closed model into AGI.

## What is disclosed

OpenAI's June 2026 Dreaming V3 announcement describes background synthesis across conversations, an editable memory summary and changes that account for time passing. Its evaluation separates useful factual continuity, applying preferences/constraints and remaining current. This is broader than a saved-note list; its private algorithms and storage architecture are not disclosed. [OpenAI announcement](https://openai.com/index/chatgpt-memory-dreaming/).

Claude's current consumer memory saves individual topics during conversations and supports separate project memory. Its documentation identifies daily 24-hour synthesis as a legacy experience. Viewing/editing memories and searching prior chats are distinct capabilities; deleting a chat does not automatically remove the memories derived from it. [Claude memory documentation](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context).

Google's developer Memory Bank exposes memory generation, consolidation, retrieval, revisions and profiles. Consumer Gemini's personalization is a separate product; these sources do not establish that Gemini uses Memory Bank internally. [Memory Bank generation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank/generate-memories), [Gemini personalization](https://support.google.com/gemini/answer/16598469?hl=en).

## Mechanisms worth implementing and testing

1. **Buffer observations before consolidation.** Memory Bank supports event-count, idle-time and interval triggers, flushing and event-ID deduplication. The transferable design is durable capture first, bounded extraction second. Preserve exact source identities across overlapping batches and process interruptions. Mnemosyne's runtime journals supplied transcript events and queues bounded jobs; host connectors determine when ingestion runs. [Event ingestion](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank/ingest-events).

2. **Separate candidate extraction from commitment.** Memory Bank distinguishes extraction from consolidation and exposes intermediate content in immutable revisions. Mnemosyne keeps proposing callbacks separate from controller skill validation, preserving source IDs and rejecting stale evidence at commitment. Repeated observations must not become independent proof merely because they were summarized twice. [Memory generation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank/generate-memories), [revisions](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank/revisions).

3. **Treat time as evidence, not completion.** OpenAI explicitly addresses memory freshness as time passes. The useful engineering consequence is to separate validity dates, review deadlines and observed event status. A deployment scheduled yesterday is not proof that deployment succeeded. Mnemosyne's validity/knowledge-time queries address dated evidence; its proposer instructions retain uncertainty about planned events. [Time-aware memory](https://openai.com/index/chatgpt-memory-dreaming/).

4. **Control capture and recall independently.** Codex documents separate controls for generating memories and using them, with idle-session processing and budget-aware behavior. Mnemosyne exposes separate capture/recall switches. Disabling capture must prevent new persistence rather than merely skipping a summary; disabling recall must block injection while permitting deliberate privacy deletion. [Codex memory controls](https://learn.chatgpt.com/docs/customization/memories).

5. **Forget sources and prevent their replay.** ChatGPT's FAQ describes removing the underlying sources as well as memories; retained history can regenerate information. Gemini similarly links removal to chats and connected sources. Mnemosyne's source-aware forgetting records a hashed ingestion tombstone, removes source-derived records and rejects replay of a forgotten ingestion identity. This protects the running store; it cannot erase copies already exported or sent to another model. [ChatGPT controls](https://help.openai.com/en/articles/8590148-memory-faq), [Gemini controls](https://support.google.com/gemini/answer/16598469?hl=en).

6. **Build project understanding with field provenance.** Memory Bank profiles use schema-defined fields and scoped revisions. The transferable design is an explicit project profile with separately supported architecture, constraints, decisions and unknowns. Mnemosyne's standing models and overview/detail hierarchy provide a starting point; automatic field-level schema extraction remains a distinct extension. [Memory profiles](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank/profiles).

7. **Expose why context was selected.** ChatGPT exposes memory sources while noting that user-visible summaries and source displays are not exhaustive. Mnemosyne can show selected records, source revisions, exclusions, conflicts and budget decisions directly because it owns its compiler. Its live inspector reads the actual store, and context packets preserve diagnostics. Completeness applies to the compiler's own selection, not to everything the underlying model knows. [Memory sources](https://help.openai.com/en/articles/8590148-memory-faq).

8. **Retrieve evidence on demand.** Anthropic's API memory tool is a client-side filesystem interface: the application owns persistence. This is different from a hosted memory service. Mnemosyne's bounded source expansion and MCP/HTTP interfaces implement the same general principle of loading specific evidence when needed. A provider-specific file-operation adapter must preserve scope and path restrictions; MCP interoperability alone is not native API-tool parity. [Claude API memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool).

9. **Keep durable memory separate from compaction and caching.** OpenAI compaction creates provider-specific continuation state; Claude compaction summarizes working context; Gemini context caching reuses input with a TTL. Cache expiration must not delete durable facts, and opaque provider state must not be promoted into portable verified evidence. [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction), [Claude compaction](https://platform.claude.com/docs/en/build-with-claude/compaction), [Gemini caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en).

10. **Evaluate selective learning before claiming it helps.** Google's Titans/MIRAS concerns neural memory architectures and test-time updates. It is not documentation of consumer Gemini memory. Novelty-based admission, retention and forgetting are hypotheses that a memory SDK can test under matched budgets; these do not modify a closed model's weights or establish AGI. [Google Research](https://research.google/blog/titans-miras-helping-ai-have-long-term-memory/).

## Evaluation requirements

Measure source fidelity, repeated errors, stale advice after changes, scope leakage, task success, model calls, context size and latency separately. Compare the same agent with no memory, a simple file/summary baseline and each enabled mechanism. Preserve failed and held-out cases. A scripted callback proves integration behavior, not a general improvement in language-model intelligence.

No paid provider calls or consumer account data were used for this research. Features inspired by these sources are implementation choices, not claims to reproduce private provider systems.
