# Mnemosyne v2 site

## Direction

A working memory instrument: generous white space, large direct typography and an inspectable evidence trail. The memorable object is a connected set of memory records whose status changes when the source changes. The site explains the implemented engine with an actual recorded run, rather than implying a simulated chat is live intelligence.

## Tokens

- Paper `#FFFFFF`: primary canvas.
- Ink `#12203A`: text and diagram structure.
- Cobalt `#234FE8`: actions, selected step and active evidence.
- Mist `#F1F4FA`: code and inspector backgrounds.
- Slate `#536176`: secondary text.
- Amber `#925300`: superseded or invalidated state on a pale background.

Helvetica Neue / Arial carries display and body text. Native monospace is reserved for executable examples, identifiers and raw context. Display type scales from 3.1rem on a phone to 6.6rem on desktop; body text is 1.05rem with 1.6 line height. Reading columns stay below 74 characters.

## Layout

The header is compact. The left-aligned hero uses a wide headline and a small evidence diagram that introduces the record motif. A full-width interactive instrument immediately follows: six sequential steps, the selected operation, readable memory records, a context inspector and actual checks. Later sections alternate short editorial explanations with useful code and a final source invitation. Documentation uses a sticky table of contents and one reading column. The comparison page uses readable prose rows with source links.

On mobile the instrument stacks its step controls, operation and inspector. All navigation remains visible; no hidden hamburger state. Tabs and step buttons have native keyboard behavior and visible focus. The demo never auto-plays. Motion is limited to short user-triggered selection transitions, disabled for reduced motion.

## Review against the brief

The proposed editorial style initially risked becoming a generic broadsheet of thin rules and numbered sections. Numbers now appear only on the real sequential demo. The primary visual structure comes from memory source, dependency and lifecycle relationships. Cobalt is functional, not a gradient wash. There are no repeated feature cards, fabricated metrics, novelty claims or stock AI illustrations.

## Content boundaries

The version is a source-build release candidate. Setup uses the actual development branch and built CLI; published npm availability is not implied. Local retrieval is lexical. Agent scopes are application-level boundaries, not database authentication. Reflection is an optional, bounded proposal pass using a caller-selected provider and controller validation. Outcome evidence is caller supplied. Forgetting covers the live store, not prior exports or already delivered context. The recorded demo uses synthetic data and no language-model inference.
