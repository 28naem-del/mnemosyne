your agent needs.

There are useful ideas across this field. Here is what informed Mnemosyne, and how its current local engine fits among them.

This compares documented approaches, not independently measured performance. Features and deployments change. Follow each primary source before choosing a system; no competitor benchmark was run for this release.

Documented emphasis

Local SQLite memory with original sources, correction cascades, bounded observation jobs, topic models, externally tested skills and scoped handoffs.

What to examine

Reproduce the lifecycle demo. Optional configured embeddings add hybrid recall. Scopes and trial validation require a trusted application controller. Agent performance remains to be evaluated.

Graphiti

Its graph model and retrieval pipeline for relationships and facts that change over time.

Mem0

Memory extraction and retrieval for applications that need persistent personalization and context.

The exact open-source or hosted configuration you plan to use. Published numbers from different configurations are not interchangeable.

The distinction between personal history and procedural experience for your use case.

OpenViking

Official repository
Documented emphasis

What to examine

Its context organization, evaluation loop, deployment requirements and current licensing terms.

Evaluate the failure cases, too.

Recall is only one part of useful memory. Test what happens when a fact changes, two sources disagree, a procedure fails, a private record must stay private, or a task moves to another agent.

LongMemEval and LoCoMo inform long-term memory evaluation. ReasoningBank informs reusable external experience. These do not establish that adding memory produces AGI.

Read the full research review for source links, practitioner reports, evaluation limits and corrections to earlier assumptions. Mnemosyne’s new local kernel was implemented without copying code from these systems.
