# Mnemosyne source-preview site

Static HTML, CSS and JavaScript. No bundler, framework, CDN, analytics or external runtime request is required. All four page routes are directory indexes, so a basic static server supports `/`, `/docs/`, `/features/` and `/compare/` without rewrite rules.

From the repository root:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory site
```

Open `http://127.0.0.1:8080/`. Serving over HTTP is required for the demo's local JSON fetch; opening `index.html` as a file displays an actionable fallback. External links open only when the visitor follows them.

## Demo evidence

`demo.json` was generated by the built engine with:

```sh
node dist/cli/index.js demo --record site/demo.json
```

The CLI intentionally refuses to overwrite an existing file. To refresh, record to a new file, check its verification results, then deliberately replace the old synthetic recording. The demo uses a real temporary SQLite database with synthetic records and no language-model inference. It records six lifecycle steps and 14 checks. The browser computes the displayed totals from the report and rejects inconsistent totals; it does not fabricate or execute a new memory run.

The record inspector displays historical snapshots. Deleting a record from the live demo store does not retroactively erase it from this existing recording. All sample data is synthetic.

## Learning-cycle evidence

`learning.json` is a second recording, generated with `node dist/cli/index.js learning-demo --record NEW_FILE.json` and deliberately copied here after checking its results. Its 13 checks exercise capture, a durable observation job, candidate gating, two executed controller trial cases, explicit sharing, correction, inspection, forgetting and replay rejection after reopening. No language model is invoked. `learning.js` validates the check identities and totals before displaying the six stages.

The live inspector is a separate authenticated HTTP service started with `mnemosy serve`. These static recordings never connect to it or retain a user's access token.

## Accessibility and behavior

The evidence demo is manually stepped and never auto-plays. Native buttons support keyboard activation, inspector tabs support arrows/Home/End, focus is visible and step changes are announced politely. Reduced-motion preferences disable transitions and smooth scrolling. The site stacks down to phone width. Raw JSON and source commands remain available when JavaScript or the demo load fails.

The dark cinematic identity is in `cinematic.css`, layered over the shared structure in `launch.css`; `styles.css` retains the recorded demo and documentation components. `launch.js` progressively enhances the mobile navigation and three-stage migration guide. Without JavaScript the navigation and all three guide panels remain available. The guide illustrates routing policy and never connects to a user's memory store. Its tabs support arrows, Home, End and Space. Mobile navigation supports Escape and restores focus across layout breakpoints.

`memory-scene.js` renders a procedural 3D memory sculpture using pinned, locally vendored Three.js 0.185.1. It supports Unified, Connected and Expanded states, horizontal drag, arrow keys, Home, reset and scene pause. This is a visual concept, not live memory data. The renderer caps pixel density, uses instanced geometry and suspends animation when hidden, outside the viewport or paused. System reduced motion and the global motion control disable ambient movement; explicit exploration remains available. Vertical scrolling and pinch zoom are preserved.

`cinematic.js` progressively adds section reveals, a chapter guide, scroll progress and restrained pointer-based card tilt. Keyboard focus reveals its target immediately. Content and navigation remain available if enhancements fail. Both modules handle page lifecycle cleanup; graphics failure restores the static illustration and disables scene controls. The canvas only becomes interactive after a successful render.

`assets/memory-architecture.png` is an original generated brand illustration, not a product screenshot. Its intrinsic dimensions reserve layout space; the hero loads it as the graphics fallback with high priority. The local Three.js modules total approximately 751 KB uncompressed (188 KB gzip); enable HTTP compression on the eventual static host. Upstream MIT attribution and verified source checksums are in `vendor/three/`. No third-party fonts or remote runtime assets are loaded. All four routes include canonical and social metadata for `mnemosy.ai`, with crawl routes in `sitemap.xml` and `robots.txt`.
