Useful experience has a source, a context and an expiry condition. Keep those relationships intact as agents and facts change.

Source-aware records

Facts, preferences, decisions and procedures

Every record has an owner, a workspace, a source and an explicit trust state. Link procedures to the facts they depend on. Record artifact revisions when your application has them.

Source references stay inspectable. The engine does not fetch a URI or independently verify a claim just because the record includes one.

Corrections that propagate

Explicit supersession and dependency invalidation

When an owner corrects a source, its earlier version becomes superseded. Dependent records become inactive so stale advice does not remain in active recall.

History remains inspectable. Similar wording alone does not make two facts identical. Conflicting active facts with the same explicit key remain visible as a conflict.

Scoped handoffs

Durable checkpoints across agent identities

Carry forward completed work, open tasks, decisions, constraints, rejected approaches and the next action. A new agent can resume explicitly shared work after the original connection closes. Link the checkpoint to its source or procedure: a correction retires the obsolete handoff, and failed or conflicted evidence prevents resume.

Records are private by default. Sharing makes a record readable within its workspace; ownership still controls edits. These are library-level access rules, so protect the database itself with your application and operating system.

Budgeted context

Citations, conflicts and uncertainty

Compile eligible memories into one context packet that fits a declared budget. Inspect its citations, omitted records and reasons for uncertainty.

Failed evidence and invalidated dependencies do not become quiet recommendations. Conflicting source groups are kept together when they fit, or withheld when they cannot be represented safely. Local retrieval starts with lexical matching. Explicitly configured embeddings add semantic candidates and optional reranking within the same source and scope checks.

Outcome-aware reflection

Optional proposer, explicit controller validation

Record success or failure with a task, verifier and evidence. Use a caller-selected model to propose reusable lessons in one bounded pass, then validate before committing.

Reflection has input, output and time limits. It rejects duplicate proposals and invented source IDs, and rechecks source revisions before a commit. This updates external memory records; it does not train the underlying model.

Evidence→Proposal→Validation→Commit

Local control

SQLite, inspection and logical snapshots

Run the local engine without an embedding service or database server. Inspect records through TypeScript, Python, CLI, MCP or the authenticated HTTP inspector. Export owned records with their complete owned provenance and restore them into the same scope.

Forgetting purges memory text and related live-store data. It does not reach existing exports, backups or already delivered context. Keep those copies under your own retention policy.

Evidence through the whole learning cycle

Capture, observations, topic models and tested skills

Capture selected files or visible chat exports. Recover the original text after summarization. Process source-cited observations with a durable queue and explicit model, input, output and time budgets.

Refresh a topic model when its evidence changes. Keep proposed skills out of advice until your controller records a passed trial. Attribute outcomes to the memories actually used. A corrected source retires its dependent advice immediately.

Time, relationships and proposed changes

Historical queries, evidence-backed links and atomic drafts

Ask what was valid at a date and what the store knew then. Link explicit entities and aliases through cited relationships, then traverse a bounded neighborhood.

Stage additions and corrections in a private draft. Preview the changes and merge only if their base evidence is still current. Drafts and background job state stay out of ordinary agent advice.

These are explicit SDK operations. Entity extraction and merging are not silently delegated to a model.

Bring your existing memories

Selected exports, reviewed before import

Move Mem0 records, Letta blocks, legacy Mnemosyne/Qdrant exports and Markdown into a private local store. Preview the exact source plan, then apply it atomically. Original record bytes remain inspectable, and renamed repeat exports reuse their stable identities.

Undo protects later work. Forget removes dependent live content and blocks the same source identity from returning. Imports are untrusted by default; seven explicit export shapes are supported.

Notice silent staleness

Last confirmation, source checks and action evidence

A fact can become outdated without anyone sending a correction. Give important evidence an explicit recheck policy. Freshness-aware recall withholds stale dependencies, while short-lived action read sets catch changed evidence before the host considers the next step.

Your controller supplies source checks and action dependencies. Age never rewrites a fact, and a read-set check does not authorize or lock an external action.
