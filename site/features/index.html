Handoffs with a next step

As facts and plans change

Keep current.

A correction should change the advice an agent carries forward. Make freshness, disagreement and dependency changes part of the memory lifecycle.

Inspect freshness checks

Corrections that propagate

Replace a source while preserving its history. Dependent lessons, summaries and handoffs become inactive. Returning to earlier document text creates a new current revision, without reviving obsolete derived advice.

Visible disagreements

Different active claims sharing an explicit fact key remain a conflict. Profiles can retain competing source-backed candidates. Similar wording alone never silently establishes that two facts are identical.

Checks for silent staleness

Set a recheck policy and supply bounded source probes. Confirmed, changed and unavailable results feed freshness-aware recall. A fact's age prompts a check; it does not invent a replacement or increase trust.

Evidence checked before action

Bind an action to its declared memory dependencies. Revalidate revisions, source-check state and outcomes immediately before the host callback. The application still supplies complete dependencies and controls the external action.

Durable observation jobs

An explicit proposer turns supplied sources into cited observations. Jobs retain state through restarts, with leases, bounded retries and call, byte and time limits. Start one drain or a finite worker when your application needs it.

Reusable topic models

Build overview and detail representations from selected evidence. Reuse unchanged generations and refresh when inputs change. Full generation checks include ancestor records, source verification and successful or failed outcomes.

Skills that earn reuse

Describe a procedure's prerequisites, steps, parameters and evidence. Proposed skills stay out of ordinary advice until the controller records a passed trial. Changed or failed supporting evidence suppresses dependent guidance.

Outcomes and reflection

Record which memories were actually used and how the task ended. Bounded reflection proposes lessons, rejects invented citations and checks source revisions before commit. These operations update external memory; the host supplies the outcome evidence.

An inspectable local system

Inspect & control.

Own the store and the decisions around it. Review proposed changes, set boundaries and rehearse recovery before relying on memory.

Read the operating boundaries

Local storage and access controls

Run the local engine without a separate database server. Records are private by default. The HTTP inspector uses scoped, revocable credentials, with independent capture, recall, read-only and destructive-operation controls.

Changes you can preview

Stage additions and corrections in a private memory branch. Inspect the proposed change, then merge atomically only while its base evidence remains current. Drafts and controller job records stay out of ordinary advice.

Backup and recovery

Take a consistent whole-database snapshot, verify its digest and database integrity, then restore to a new path. Preserve workspaces, pending jobs and erasure tombstones. Scoped exports remain a separate transfer option.

Rehearse recovery

Forgetting across the lifecycle

Erase source generations and dependent live content. Hashed tombstones block replay after restart, including across full and gradual migration when the source identity matches. Legacy stores and existing external copies remain under your own retention controls.

Measure benefit and harm

Compare no memory, recent history, lexical memory and adaptive context under one reader and budget policy. Track answer and action correctness, grounding, stale actions and negative transfer, keeping failed attempts in the denominator.

Know what you are building on.

These capabilities are implemented in the 2.0.0-rc.8 source candidate. Your application supplies trusted scope, selected source checks and model callbacks. Provider tools do not transfer consumer account memories; export profiles do not recreate every upstream feature.

Gradual adoption measures the queries seen so far and continues to check the old backend. Recovery files are plaintext, erasure cannot reach existing backups, and production identity, remote TLS and managed synchronization remain application work. The documentation makes those boundaries explicit.
