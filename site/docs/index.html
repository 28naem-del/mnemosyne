Build from source

Use Node.js 22.16 or newer and npm. This guide targets 2.0.0-rc.2 on the development branch. It does not assume that v2 is available from the npm registry.

Terminal
git clone --branch codex/mnemosyne-2-local-learning \
  https://github.com/28naem-del/mnemosyne.git
cd mnemosyne
npm ci
npm run check
npm run demo
npm run demo:learning

The demo creates an isolated temporary SQLite database, runs two agent identities through six steps, reports its checks and removes the temporary store. It makes no LLM calls.

Store your first memory

Every CLI memory command needs a database path, workspace and agent. This example creates a private record owned by builder. Add --share only when other agents in that workspace should be able to read it.

Run from the repository
node dist/cli/index.js store \
  --db ./project-memory.sqlite \
  --workspace my-project --agent builder \
  --text "Run the accessibility check before release." \
  --source "project://release-checklist"

node dist/cli/index.js recall \
  --db ./project-memory.sqlite \
  --workspace my-project --agent builder \
  --query "release accessibility"

The CLI stores observed source assertions by default. The TypeScript store defaults to untrusted records unless the caller chooses a trust level. Repeated retrieval never upgrades a memory into verified evidence.

Connect an MCP client

The CLI starts a stdio MCP server. Configure your client to launch the command below, replacing the example paths for your machine.

MCP client configuration example
{
  "mcpServers": {
    "mnemosyne": {
      "command": "node",
      "args": [
        "/absolute/path/to/mnemosyne/dist/cli/index.js",
        "mcp",
        "--db", "/absolute/path/to/project-memory.sqlite",
        "--workspace", "my-project",
        "--agent", "builder"
      ]
    }
  }
}

The configuration shape depends on your client. Use the absolute path to your Node executable as command if the client cannot resolve node.

Available tools include memory_store, memory_recall, memory_context, memory_inspect, memory_checkpoint, memory_resume and memory_correct. The controller fixes workspace and agent at launch; the model cannot select a different scope in a tool call.

  • --read-only exposes only read operations.
  • --allow-destructive explicitly exposes memory_forget. It is absent by default.
  • Verified trust, outcome recording and reflection commits are controller operations, not model-facing MCP tools.

Memory is reference data. A recalled instruction or checkpoint does not grant permission to publish, delete, buy or run a command.

Use the local TypeScript API

From the source checkout, import the built local entry point. Close the database when the owning process is done.

ES module · run from the repository
import { createLocalMemory } from './dist/local/index.js';

const memory = createLocalMemory({
  path: './project-memory.sqlite',
  workspaceId: 'my-project',
  agentId: 'builder',
});

try {
  const brief = memory.store({
    text: 'Catalogue images use a 1600 x 1200 canvas.',
    kind: 'decision',
    key: 'catalogue-output',
    trust: 'observed',
    visibility: 'workspace',
    source: { uri: 'project://catalogue/brief-v2' },
  });

  memory.store({
    text: 'Fit the original image inside 1600 x 1200; pad, never stretch.',
    kind: 'procedure',
    trust: 'observed',
    visibility: 'workspace',
    source: { uri: 'project://catalogue/resize-procedure' },
    dependencies: [brief.id],
  });

  const packet = memory.compile({
    query: 'catalogue image canvas',
    maxTokens: 4096,
  });
  console.log(packet.text);
} finally {
  memory.close();
}

Send packet.text as reference context to your chosen model. The budget covers that text; additional structured diagnostics are outside it. By default the counter uses a conservative UTF-8 byte upper bound. Supply a compatible tokenCounter when you need a model-specific count.

Correct the source, inspect the effect

memory.correct(id, { text, source, reason }) creates a replacement and supersedes the original. Dependent lessons become inactive. You can inspect the historical records, while active recall excludes them.

Use memory.inspect({ includeInactive: true }) to review history, or memory.get(id) to inspect a visible record. Different active texts sharing an explicit fact key remain a conflict; the compiler does not silently choose a winner.

memory.checkpoint(...) records a task’s goal, completed and pending work, decisions, constraints, artifacts, rejected approaches and next action. Set dependencies: [sourceOrProcedureId] when its next action relies on a memory. memory.resume(taskId) retrieves eligible state; corrected, failed or conflicted evidence prevents obsolete handoffs from resuming. If multiple owners share conflicting checkpoints for the same task, resolve that ambiguity before resuming.

Logical export includes owned records with complete owned provenance. It can omit records that depend on another agent’s data; inspect the omitted count. Import is scoped to the same workspace and agent. Snapshots have record and byte limits.

Add a bounded reflection pass

Import reflect and commitVerifiedLesson from ./dist/reflection/index.js. You supply a proposer function using your chosen model or service. Mnemosyne chooses no provider and adds no paid fallback.

  1. reflect(memory, options) compiles eligible evidence and makes at most one proposing call.
  2. The response is checked for output limits, duplicate proposals and fabricated source IDs. Proposing writes no memory.
  3. Your controller evaluates the proposal against a task or environment.
  4. commitVerifiedLesson requires passed validation with evidence, a verifier and a task ID, then checks that source revisions remain valid.

A committed lesson remains an observed synthesis with validation metadata. Caller-supplied validation is not authenticated proof of truth. Timeouts signal cancellation; your provider must honor the signal to stop its own compute.

Read the reflection API and its limits.

Use the experience runtime

The runtime adds selected-file and visible-transcript capture, original-source inspection, bounded durable observation jobs, source-backed topic models and skills that require controller trials before activation.

Use capture --file PATH --adapter text for a selected document or choose generic, codex or claude for JSONL. Add --watch to keep that foreground process synchronized. These commands require the same database, workspace and agent flags shown above.

serve --token-file PATH starts the local HTTP service and live inspector. The token file must contain a private, unpredictable secret of at least 32 bytes. Python applications can use the bundled standard-library client. The inspector displays actual records from your running store after authentication.

Provider configuration is explicit. Hybrid retrieval uses a selected embedding endpoint and model; observation jobs use a selected proposer. No cloud service or paid fallback is enabled automatically.

Follow the complete runtime guide with runnable examples for configuration, trials, branches, entity relationships and access controls.

Know the boundaries

  • Retrieval is configurable. The default lexical search needs overlapping words. The local store also supports explicitly configured embeddings and hybrid recall. Model-based semantic quality depends on the chosen provider and remains to be evaluated on your tasks.
  • Scopes are application boundaries. Anyone with direct database access or control of the process can act outside them. Use your operating system and application authentication to protect the store.
  • Outcome evidence comes from the controller. Success and failure records help evaluate reusable advice. They are not independent authentication or model training.
  • Forget purges the live store. It cannot remove prior exports, backups or context already delivered to a model.
  • Memory is one component of an agent. This release does not establish AGI or a published advantage on agent benchmarks.

For implementation details and the research behind these choices, use the repository documentation.
